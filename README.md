# Магазин фермерских продуктов «У дома»

**Статус проекта:** В активной разработке

## 📝 Описание
Информационная система для автоматизации бизнес-процессов розничного магазина фермерских продуктов. Магазин ориентирован на жителей района и закупает товары у местных фермерских хозяйств.

Проект представляет собой десктопное приложение, которое решает следующие задачи:
- Учёт поставщиков и номенклатуры товаров.
- Оформление закупок и автоматическое обновление остатков на складе.
- Быстрое оформление розничных продаж.
- Ведение базы клиентов и программы лояльности (начисление/списание баллов).
- Формирование отчётов по выручке, прибыли и объёмам закупок.

## ⚙️ Установка и запуск

Для запуска проекта на вашем компьютере выполните следующие шаги:

**1. Клонирование репозитория**
- Откройте терминал (или PowerShell) и скопируйте проект на свой компьютер:

```git clone https://github.com/lifeiliv33/farmer-market-project.git```

**2. Настройка базы данных**
- Откройте MS SQL Server Management Studio (SSMS).
- Выполните SQL-скрипт database_creation.sql (находится в папке 02_Database/), чтобы создать все таблицы и связи.

**3. Запуск приложения**
- Откройте файл решения FarmerMarket.sln в Visual Studio.
- Проверьте строку подключения к вашей БД в файле App.config.
- Нажмите F5 (или Build → Start Debugging), чтобы собрать и запустить приложение.

### Требования
Для работы с проектом вам потребуется:
- **ОС:** Windows 10 или 11.
- **Среда разработки:** Visual Studio 2022 (с установленным компонентом «Разработка классических приложений .NET»).
- **База данных:** MS SQL Server (Express или Developer Edition) и SSMS (SQL Server Management Studio).
- **.NET Runtime:** .NET 6.0 или выше.

## 💻 Примеры использования

Ниже приведены базовые сценарии работы с приложением для разных ролей.

**Сценарий 1: Продавец**
1. Продавец авторизуется в системе.
2. Переходит в модуль **«Продажи»**.
3. Находит товар через поиск или сканирует штрихкод.
4. Добавляет товары в чек. Система автоматически считает итоговую сумму и наценку.
5. Если у покупателя есть карта лояльности, продавец вводит её номер. Система применяет скидку или списывает накопленные баллы.
6. Выбирается способ оплаты (наличные или карта).
7. Чек закрывается. Остатки на складе автоматически уменьшаются.

**Сценарий 2: Товаровед**
1. Товаровед авторизуется в системе.
2. Переходит в модуль **«Закупки»**.
3. Создаёт новую закупку, выбирает поставщика (например, Ферма «Заря»).
4. Добавляет позиции: молоко (10 шт.), сыр (5 кг). Указывает закупочную цену.
5. Подтверждает приёмку.
6. Система автоматически увеличивает остатки на складе и фиксирует сумму закупки.

**Сценарий 3: Администратор**
1. Администратор авторизуется в системе и попадает в главное меню (доступны все модули без ограничений).
2. Переходит в модуль **«Сотрудники»** и добавляет нового продавца, назначая ему роль и права доступа.
3. Открывает модуль **«Отчёты»**, чтобы проанализировать работу магазина за неделю.
4. Настраивает фильтры: выбирает период (последние 7 дней) и категорию товаров (например, «Молочное»).
5. Система формирует сводку: выручка, прибыль, доля постоянных клиентов и объёмы закупок у фермеров.
6. Администратор видит, что сыр от поставщика «Сыроварня Луга» продаётся плохо, и принимает решение заказать его меньше в следующем месяце.
7. При необходимости администратор может зайти в модуль **«Склад»** и оформить списание просроченного товара, указав причину и ответственного сотрудника.
